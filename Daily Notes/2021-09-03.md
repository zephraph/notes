## Review of 461
- Related themes from onboarding philosophy doc
	- Prefer native HTML controls wherever possible
	- Prefer component APIs that rely on and even teach web standards
		- Example: instead of an `error` prop that gets passed through to `aria-invalid`, use `aria-invalid` directly and use usage comments to explain how to use it
	- A conceptual unit like an input group does not need to be a single component
		- Prefer exposing multiple components that are explicitly composed at the call site over a single component with a complex props API that takes in all the info necessary to arrange things. [Reach UI](https://reach.tech/) is a great model for this.
